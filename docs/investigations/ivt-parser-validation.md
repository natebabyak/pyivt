# Data-directory fix and validation record

## Finding

The data decoder previously calculated every entry position as
`directory_start + 8 * ordinal`. It ignored the native data slot's paging flag,
capacity and declared count. The existing metadata reader already understood
the shared slot representation. The fix reuses that checked ordinal resolver
for data and decodes each value component from its recorded absolute offset.

This is support for the native paged-directory variant, corresponding to
category G in `problems.md`. The old flat interpretation reads a pointer table
as records. The native algorithm, exact instruction addresses and artifact
identity are documented in [the static investigation](ivt-native-directory.md).
The `0x8000` spacing follows from 4096 entries times eight bytes, rather than
from a special offset formula or a value-page size.

The native reader also establishes that the two `u16` length fields mean content
length and allocation length. Data reads now use the content length, with
`0 < content <= allocation`; they no longer apply the old heuristic comparing
two supposed size copies. Record offsets remain absolute. Entirely zero
directory entries retain the supported zero-component representation. Nonblank
malformed entries fail, with ordinal, resolved position, raw bytes/offset,
content/allocation lengths, directory start/count, file size and failure reason.
Arithmetic and conversions along the entry-resolution path are checked.

There is no filename, reported-offset, or raw-value special case in the parser.
The Python API and output schema are unchanged.

## Original report: still unverified

The exact UNC path in `problems.md` returned "Cannot find path ... because it
does not exist" even when retried outside the filesystem sandbox. No original
NAICS234 bytes or trusted full export were available. Consequently:

- The actual original file's header, paging flag, entry count and components
  have **not** been inspected.
- The native paging rule is proven; its selection by that particular file is
  still an inference consistent with the reported pointer sequence.
- Successful conversion and independent full-output equality for NAICS234 are
  **not** claimed. The original report's completion criteria remain open for
  this file.

`tests/test_arrow_regression.py` accepts
`PYIVT_REGRESSION_NAICS234_PATH` and
`PYIVT_REGRESSION_NAICS234_EXPECTED_PARQUET`. A provided case must have an
independent complete oracle; missing files or an omitted oracle fail. The test
checks the complete schema, shape, every column and every null position. The
reference needs the same documented dimension order and full field projection;
it must not be generated by the parser under test. No browser is required by
the parser or test.

## Coverage boundaries

- Native unit tests cross directory ordinals 4095/4096 and 8191/8192, preserve
  holes and the partial last page, and deliberately reorder physical pages.
  They cover bad offsets, one-byte overruns, invalid lengths, truncated pointers
  and entries, zero/unsupported page sizes, count bounds, and arithmetic overflow.
- Python corruption cases check that paged-header/count/pointer errors surface
  as exceptions through the unchanged public API.
- All local corpus Arrow tests now check exact Cartesian coordinates/order,
  member-to-axis alignment and status/null consistency. Independent canivt
  comparisons use explicit named projections rather than searching for any
  column with matching values.
- canivt 0.5.0 at `219486b22413f42971ff6d8b3e26b1498af3a01e` loses the DGUID
  column for 98-10-0018 while warning about heuristic geography recovery. The
  official CSV establishes the correct Quebec DGUID, so that field alone uses
  the official source. Other projected canivt fields remain strict comparisons.
- The committed offline oracle runs in CI without R, Beyond, network access or
  optional local Parquets. Optional local Parquets continue to broaden coverage.
- The official CSV does not supply all French/native auxiliary fields or raw
  annotations; their complete equality is covered by the synthetic typed test,
  not claimed as an independent export of an external IVT.

Native upper member-type byte semantics and the time epoch's derivation were
not fully proven by this bounded binary pass. The separate static report names
those limits. The patch does not alter existing member/date decoding.
